## 这是什么

风月酿研所是一款**给家酿爱好者自己用的配方软件**。

你在纸上、在 Excel 里、在聊天记录里攒下的那些配方，它都能接住：选一个风格，填几个参数，糖度、酒精度、苦度、色度、原料用量立刻算给你看；酿完之后把实测数据记回来，下一锅就知道该怎么调。

它不联网、不注册、不上传。配方只存在你自己的电脑和手机里。想给别人看，用**分享码**——一串字符，复制粘贴，对方打开软件就能还原出你那份配方的每一个参数。

> 名字里的"风月"，是喝酒那点事；"酿研所"，是把它当正经事研究的地方。

## 主要功能

### 一、原料库与配方库

不是一张名字清单，是能直接下锅算账的数据。

| 库 | 数量 | 每条包含什么 |
|---|---|---|
| 麦芽与谷物 | 70 | 出糖率（ppg）、色度（°L/EBC）、用量上限、糖化力、是否需糖化、风味、适用酒款 |
| 酒花 | 95 | α 酸、产地、香型、投放阶段建议、苦味/香气倾向 |
| 酵母 | 59 | 衰减度、发酵温度区间、沉降性、风味特征、扩培建议 |
| 辅料 | 53 | 用途、用量上限、对口感与泡沫的影响 |
| 水质档案 | 10 | 典型城市/风格水质，用于盐类调整计算 |
| BJCP 风格 | 105 | OG/FG/IBU/色度区间、关键风味描述、常见缺陷 |
| 经典配方 | 50 | 拆成可编辑的原料行，可直接调用或改写 |

**数据诚实原则**：每条原料标注置信度——A 为多源交叉验证，B 为单一权威源，C 明确写"需查厂商 COA 后再用"。查不到规格表的字段宁可留空，也不编一个精确到小数点的假数字。

### 二、计算内核

改一个数，全表跟着变——这是整套软件的地基。

- **实时联动**：批次量、糖化效率、原料用量、酒花投放，任一参数变动，糖度（OG/FG）、酒精度（ABV）、苦度（IBU）、色度（SRM/EBC）与原料清单同屏重算
- **公式全公开**：每个指标都能展开看到完整表达式与出处，例如出糖点数 `points = Σ(ppg × kg × 8.34540 × 效率) / L`
- **常量可校准**：系统效率、酒花利用率等常量可自行调整，用来对齐你那套设备的真实表现
- **感知苦度**：同样的 40 IBU，麦芽甜度不同喝着完全不同，软件按甜苦平衡给出"实际喝起来多苦"
- **酵母扩培**：要几步、需要多少 DME、每步多久，直接给可执行方案
- **水质匹配**：选目标风格，算出还需要补多少硫酸盐、氯化物，折成克数

### 三、配方设计与校验

- **超量告警**：不只是"超过上限"，而是说清超了会怎样——比如黑麦超过 30%，麦醪会像水泥，必须加稻壳并做蛋白质休止
- **配方体检**：一键检查比例失衡、参数越界、单位冲突，逐条列出来
- **逐行比对**：同款酒的两版配方，差在哪一行、差多少，一屏看清
- **配方谱系**：这版从哪版改来的，一路追到源头，改坏了能退回上一代
- **库存与采购**：按配方自动算"还差多少麦芽、多少酒花"

### 四、批次记录与复盘

- **配方 → 批次 → 实测**：同一份配方每酿一次留一条记录，含实测 OG/FG、发酵曲线、FG 预测偏差
- **校准系统效率**：酿三锅之后，你才知道自己那套设备真实的出糖率是多少
- **酿造日计划**：把糖化、洗糟、煮沸、投放、降温排成时间轴
- **年度统计**：一年酿了几锅、花了多少、哪款最值得复酿

### 五、输出与呈现

- **配方卡**：一键导出长图，发群里、贴到配方本上都行
- **酒标设计器**：配方顺手配一张瓶标，送人不再手写标签
- **报表与打印**：排版按打印几何调过，直接出 PDF 或纸本
- **品鉴打分**：37 个风味锚点，喝完对着打分，下次知道该往哪调

### 六、会教人的软件

- **121 条术语**：正文里点一下就解释——糖化、休止、双乙酰、衰减度，不用跳出软件去翻书
- **82 条知识卡**：用到哪讲到哪，"为什么这一步要 65°C""为什么这锅要后投酒花"
- 术语与知识卡都按指标 / 工艺 / 原料三类归档，按场景出现，不堆在角落里

## 特色功能：分享码

> 一句话：**把一份配方，压成一串能贴在聊天框里的字符。**

### 它解决的是什么问题

家酿圈子交换配方，一直很别扭：

| 传统做法 | 麻烦在哪 |
|---|---|
| 截图 | 参数看不全，比例算不出，对方还得手动抄一遍 |
| 发 Excel | 得传文件、对版本、字段对不上就废 |
| 网盘 / 云文档链接 | 过一阵就失效；对方还得注册账号、装软件、申请权限 |
| 口头说 | "大概 5 公斤麦芽、两把酒花"——只能意会 |

分享码把这件事变成了**一行文本**：

```
BL2.eyJ0IjoicmVjaXBlIiwidi......（后面是一长串字母数字）
```

复制、粘贴到微信/QQ/论坛/邮件，对方在软件里点「导入」粘进去，**配料表、参数、酒标、备注全部原样还原**，包括你没写在备注里的那些细节。

不需要账号，不需要联网，不需要服务器。这一串字符本身就携带了全部信息。

### 能分享什么

不是只能传配方：

| 类型 | 分享码前缀 | 内容 |
|---|---|---|
| 单个配方 | `BL1.` / `BL2.` | 完整配料表、工艺参数、备注、酒标引用 |
| 分享包 | `BZ1.` | 一次打包多份内容，适合"我这一季的四款酒" |
| 公式配置 | `BF1.` | 你调过的常量与自定义公式，别人可以直接套用你的算法口径 |

在「分享中心」里，可以勾选任意组合打成一个包：

- 配方
- 批次记录（含实测数据与发酵曲线）
- 酿造日计划
- 酒标
- 公式

也就是说，**你连"我这锅实际怎么走的"都能一起发过去**，而不只是纸面上的配方。

### 怎么用：三步

1. **生成**：打开「分享」，选类型（配方 / 批次 / 酿造日 / 酒标 / 公式 / 自定义组合），点生成，得到一串码
2. **传递**：复制。发微信、发 QQ 群、贴论坛、写进邮件，随便
3. **导入**：对方在软件里打开「分享 → 导入」，粘贴，**先看到预览**——里面有什么、会写到哪里，一条条列清楚；点「确认导入」才真正写进他的库

第 3 步的"先预览、后落库"是刻意设计的：收到别人发来的码，你不会被莫名其妙地覆盖掉自己的配方。

### 为什么它可靠

- **版本内嵌**：码里带格式版本号。老版本打开新版本的码，会明确提示"这个码来自更新版本，请升级后再导入"，而不是解出一堆乱码
- **结构校验**：解码后逐字段校验，不合法的记录会被丢弃并计数，不会把半截数据写进你的库
- **识别明确**：不是分享码的文本（比如别家软件的 JSON）会直接告诉你"这不是分享码"，不会误导入
- **不联网**：整个编解码在本机完成，没有任何服务端参与，也就不存在"链接过期""服务停运"
- **可读可存**：分享码就是纯文本，可以存在记事本里、写在配方本边上，十年后还能粘回来

### 三个真实场景

**① 群里问诊**
"我这锅 IPA 苦得发涩，是不是酒花投早了？"——附上分享码。懂行的人导入后，看到的是你的完整参数和水质，不用再问"你 OG 多少、用了什么水、几度糖化"。

**② 朋友要配方**
"上次那款燕麦世涛给我抄一下"——发一串码，比发文件快，也比截图全。

**③ 复刻与迭代**
看到别人分享的配方，导入后改两个参数，另存一版，再用逐行比对看差异；酿完把实测数据记回来，连同批次一起分享回去。**配方在圈子里就这样一轮轮被改好。**

> 分享码不是云同步，也不是备份。它的定位很明确：**让一份配方在人与人之间流动起来，且不依赖任何服务器。**

## 源码

应用源码已公开在本仓库 [`src/`](src) —— 就是 v1.3 安装包里实际运行的那份代码，从 `resources/app.asar` 原样取出，未做删改。

**技术栈**

| 层 | 选型 | 说明 |
|---|---|---|
| 界面 | 原生 HTML / CSS / JavaScript | 无框架、无打包器、无构建步骤，改完刷新即生效 |
| 图标 | 内联 SVG + PNG | 无图标字体依赖 |
| 数据 | `localStorage` | 不连数据库，配方只在本机 |
| 外壳 | Electron 45 | 主进程只管窗口、菜单、单实例、剪贴板、启动备份 |
| 安装包 | NSIS 3.10 | 装到用户目录，免管理员权限 |

**目录结构**

```
src/
├─ main.js            Electron 主进程：窗口位置记忆、缩放记忆、菜单、单实例、启动备份、崩溃兜底
├─ preload.js         只向「关于」页暴露 4 个方法（复制 / 关窗 / 开帮助）
├─ package.json
├─ assets/            应用图标（ico + 多尺寸 png）
└─ web/               应用本体
   ├─ index.html
   ├─ css/            9 个样式文件，按版本分层，style.css 为基底
   ├─ js/             58 个模块，按编号顺序加载（00-core → 60-app）
   └─ desktop/        独立窗口：使用说明 help.html、关于 about.html
build/
└─ installer.nsi      NSIS 安装包脚本（参考模板）
```

网页版由 GitHub Pages 托管，直接打开 <https://zj1414801987.github.io/fengyue-brewlab/> 就能用，数据存在浏览器 localStorage，与桌面版各自独立。

**本地运行**

```bash
cd src
npm install      # 只装 electron 一个开发依赖
npm start
```

**打包成 exe**

1. `npx @electron/asar pack . ../build/app.asar`，把 `app.asar` 放进 Electron 运行时的 `resources/`
2. 用 `rcedit` 给 `electron.exe` 写图标与版本信息，并改名
3. `makensis build/installer.nsi` 出安装包（脚本内的 `OUTDIR` 按本机路径改）

**几处刻意为之的设计**

- **分享码的协议标识固定为 `BrewLab`**（`web/js/28-share-code.js`）：品牌换了、协议没换——改了它，历史分享码全部失效。
- **公式求值不用 `eval`**：`web/js/43a-formulas.js` 走 tokenizer + 调度场算法转 RPN 再求值。
- **计算内核与界面分离**：`js/2x` 是纯计算、`js/4x` 是渲染，改界面不会碰到算错的风险面。
- **升级要清旧 exe**：主程序文件名带版本号，覆盖安装不清理会残留 200MB+ 的旧版，脚本里已用通配符删除。
